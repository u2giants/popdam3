# QUARANTINE LIST for the "Database Contract Tests" workflow.

# Every file listed here IS STILL EXECUTED on every run and its full output is still
# printed and uploaded. Only its RESULT is prevented from failing the job.
#
# READ THIS BEFORE ADDING A LINE
# ------------------------------
# This list exists for ONE reason: a test that cannot hold on a FROM-EMPTY database is
# not a failing test, it is a test aimed at a different target. It is NOT a place to
# park a test that found a real defect. Adding a line to make a red job green, without
# the reason being true, converts this workflow back into the thing #695 was filed
# about -- a check that is present but enforces nothing.
#
# Every line is `<filename>  # <reason>`. A line with no reason is not valid.
#
# WHY SO MANY, AND WHAT IT MEANS (measured 2026-08-11, the first execution ever)
# -----------------------------------------------------------------------------
# Replaying all 429 migrations into an empty Supabase database applies 363 and FAILS 66.
# The repository's migration history is NOT self-contained: it was adopted on top of an
# already-populated database, so objects such as `public.assets`, the legacy popdam
# tables and the `dflow.*` mirrors exist in preview and production without any migration
# here having created them. Everything downstream of those 66 is therefore missing from
# the ephemeral schema, and a second group of tests needs seeded reference data
# (authenticated profiles, Customers, Vendors, real Licensor rows) that an empty
# database has none of by definition.
#
# So this lane proves the subset of the contract that is provable from the repository
# alone. THAT IS NOT THE WHOLE CONTRACT. The quarantined files below still have to be
# run against preview by hand before a production promotion; making CI run them for real
# needs a captured pre-adoption baseline migration and a test-fixture seed, neither of
# which exists yet. Nothing here should be read as "these have passed".
