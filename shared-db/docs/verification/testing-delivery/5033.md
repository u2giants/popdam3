# Testing and delivery process repair — #5033

Owner: Codex, issue #5033. This record belongs to the existing development and
merge workflow; it introduces no alternative release route.

## Observed failures

The #4427 closeout exposed avoidable delays: relevant offline guards were omitted
before paid review; a review request was treated as running without a worker
acknowledgement; mutable review inputs invalidated a completed review; a failed
merge group retained the serial lane until its full healthy-check budget expired.
PR #5023 ultimately merged and the production certificate passed. That application
outcome stays closed; this issue repairs the delivery process.

## Bounded repair scope and acceptance

- Reuse the existing offline guards as a quick local pre-review check, catching
  detector hash drift and the complete affected RLS test family before expensive runs.
- End a failed, removed or replaced merge group's own hold promptly; retain the
  healthy pending-check budget, production exclusion and ownership-proven release.
- Document review-start acknowledgement, frozen inputs, early completion
  prerequisites and one final ready candidate before review.
- Prove negative cases with regression tests and verify actual required CI and
  the guarded merge on the finished implementation. No production SQL is needed.

## Implementation and verification

The local preflight reuses six existing guard/test groups with a 60-second
per-step and 180-second overall budget, stops at the first error and verifies
native source identity before and after. Its actual integrated run passed all
980 coordination tests, 72 throughput tests, 39 RLS/parser tests and 309 focused Python tests. Fifteen
new regressions cover unavailable dependencies, first-failure ordering, timeouts,
changed inputs and global-budget exhaustion. The pinned production detector
baseline is unchanged; new truth dispositions bind only the new source sites.

The parallel CI run exposed a native acquisition-inventory test that recognized
only direct lane calls. It now recognizes the existing trusted wait wrapper
while still requiring all four guarded/database acquisitions and their original
admission/head assertions. The early preflight now also runs this native
coordination family, queue workflow, hold and busy-waiter tests so this exact
failure is caught before paid review.

The queue monitor uses exact-group, server-reported `isRequired` flags with
read-only credentials to notice a failed required check. It never authorizes a
merge or substitutes for the existing full effective-settings preflight. Empty
or pending reports keep the original 900-second healthy budget; failed checks,
ejection, changed heads and replaced groups stop the hold. Existing failure
cleanup alone releases the ownership-proven lane. No administrative secret is
added to merge-group code. Guarded merge uses the existing trusted busy-lane
waiter, retaining immediate refusal for every non-occupancy gate. Its job keeps
the original 20-minute execution margin after the 15-minute busy-lane wait.
Fixed GraphQL query POSTs explicitly use the existing transport idempotency
proof to retain four transient-failure attempts while quota waiting stays zero.
A transport-level 502 regression proves the retry, and a real read-only
first-page probe returned 30 contexts on the historical failed group, correctly
identifying the required SQL failure. The cursor was already nullable; the
review report's non-null-cursor finding was disproved against actual source.

The development guide records review-worker acknowledgement, frozen review
inputs, an initial bounded performance smoke and early native-completion
prerequisites. Existing full CI, independent review, production exclusion,
foreign ownership and proof requirements remain binding. Regression tests run
in the existing engineering CI path.
