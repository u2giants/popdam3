`scripts/proofs/4874-read-resource.json` is the exact bounded resource/action contract. It is not execution authority. Independent security/final review must approve this source HEAD and that contract; the native database gate must accept that same review immediately before execution. The CLI invokes that gate before loading runtime packages or starting authentication. Review of a different PR or the historical private proposal grants no permission here. Root owns protected landing, target/role/catalog qualification, execution, comparison and business closure.

The shared target constant is reused from `scripts/lib/designflow-db-catalog.mjs`. No existing helper safely implements the specific genuine-account read-plan lifecycle, so `scripts/qualify-authenticated-rls-read.mjs` isolates reusable pure workload/sanitization/qualification functions and a thin gated CLI. Tests use only mocked accounts, tokens and database calls; they never connect to a service.

Exact four query workloads are `SELECT count(*)::integer AS bounded_count FROM (SELECT 1 FROM public.<fixed table> LIMIT <fixed limit>) AS bounded`: profiles200, admin_config200, assets1000, style_groups1000. Each has one warmup and ten samples, median and p95, numeric allowlisted plans. This is representative read qualification, not every-policy, CRUD or whole-app acceptance. No ordering/predicate/count-scope changes are introduced. Live cardinality, permissions and planner/settings drift must be disclosed before comparing historical timings; repeat any >10% median regression under the same bounded workload without changing production to manufacture a baseline.

Runtime uses the already approved SDK2.97.0 and pg8.23.1 from existing protected dependency roots (`RLS_SDK_ROOT`, `RLS_PG_ROOT`), provider CA path (`RLS_CA_FILE`), and protected environment injection (`QA_EMAIL`, `QA_PASSWORD`, `PROD_DB_PASSWORD`, `SUPABASE_PUBLISHABLE_KEY`). No actual values, machine-local roots, approved-user identity, keys or real results belong in this repository. Package version checks do not authorize replacing a dependency root with unreviewed code; root verifies actual runtime custody before execution.

CLI arguments are `--reviewer-approval <native report> --output <new private absolute report>`. Root runs it through the existing protected credential runner; the owner is never asked to run a command. No account creation, escalation, invented JWT, migration, worker/flag changes, schema/ACL/policy change or SQL write exists in the harness. Ordinary login creates provider-side authentication/audit effects that do not roll back; local signout is mandatory. This harness does not prove the separate owning-app write/cleanup requirement.

Every opened transaction begins with `BEGIN READ ONLY` before any query or role switch, then asserts read-only/default/database/optional project setting, fixes15-second statement and3-second lock timeouts, verifies installed version20261021190604, installs the full server-validated JWT context and proves nonowner/nonbypass authenticated administrator. TLS requires a provider CA and exact project pooler route. It resets role and rechecks ledger after the samples. Every failure rolls back any opened transaction, closes the connection and locally signs out any obtained session; cleanup failure fails acceptance.

Output is reserved before login, regular file only, exclusive/no-follow0600. Reports contain fixed identities for workload tables, counts, version, booleans and numeric sanitized plan metadata. Predicates, outputs, subjects, email, credentials and raw exceptions are discarded. Standard output is only pass/fail plus workload/plan counts. A report/output-write failure is never success. Root retains reports and authentication/runtime evidence privately and independently verifies restoration; successful code tests or source merge cannot stand in for live proof.
