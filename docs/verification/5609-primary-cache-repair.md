## Reusable bounded repair

`scripts/reconcile-primary-thumbnail-cache.mjs` defaults to dry run. It uses the existing REST/service-role credential environment, verifies an independently supplied expected project reference against the configured HTTPS URL, and adds no endpoint, privilege or SQL. It keyset-pages at most 100,000 groups and refuses more than 1,500 drift candidates before any write. Both HTTP activity and the row loop have a twenty-minute budget; each request is limited to fifteen seconds.

A candidate must have a selected, active asset belonging to that same group. Out-of-scope primary references refuse the operation. The only PATCH fields are `primary_thumbnail_url` and `primary_thumbnail_error`. Primary ID, ranking, asset rows, business fields and source dates are preserved. Existing automatic `updated_at` processing still runs and is excluded from the all-other-fields comparison.

Before every PATCH, a complete private row/source preimage is flushed to disk. The group ID, selected-primary ID, exact group `updated_at`, and both old cache values guard the conditional request. The selected asset and group are reread before and after; a changed primary or unrelated field is a failed conflict, not overwritten. A zero-row conditional PATCH is skipped and fails the report. A source-only change is re-evaluated at most three attempts per candidate. REST cannot lock the source asset and group together: post-write verification and bounded retry explicitly cover that race, and continuous churn fails rather than claiming success. Final verification requires zero drift, no conflicts/unresolved candidates, and unchanged primary IDs/other fields for repaired groups.

The tool requires `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_EXPECTED_PROJECT_REF`, and an absolute new `PRIMARY_CACHE_REPAIR_PACKET` directory. Secret values are injected through the existing protected runner, never arguments/files/output. A newly created packet has mode 0700; exclusive before/after JSONL and aggregate receipt files have mode 0600. Existing paths/symlinks refuse. Private row/source contents remain local; stdout and public evidence contain only aggregate counts, timestamps and a backup-content hash. `--apply` is a distinct, explicit action after the coordinator reviews the actual dry-run receipt and production gate. No cleanup or secret rotation is part of this tool.

Mock regressions cover dry-run non-writing, flushed backup-before-write, switched primary, optimistic conflict, source change before/after PATCH, continuous churn refusal, null/error clearing, idempotency, candidate cap, unrelated-field preservation, exact REST guards and target mismatch. Existing failure evidence and acceptance thresholds stay on the same shared-db issue. Repairing these rows alone does not establish full-day acceptance or activate its successor interval.
