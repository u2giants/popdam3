# Codebase audit — 2026-10-21

Five parallel reviewers read the web app, the Railway worker, the Supabase edge
functions, the agents, the desktop helper and the scripts. Every finding below
was verified by reading the code; the first section landed in the audit PR,
the second section is the backlog, most urgent first, each with a suggested
owner. Nothing here changes the shared database.

## Fixed in the audit PR

Web app (`src/`)
- "View as member" never worked: the role-level `ImpersonationProvider` was
  defined but never mounted, so `useIsAdmin` and the header read a no-op
  default context. Now mounted in `App.tsx`.
- Realtime subscriptions in `useAgentStatus`, `useScanProgress` and
  `useCrawlProgress` shared one channel topic; whichever consumer unmounted
  first tore down the live subscription for the others. Topics are now unique
  per mount, and both status hooks re-evaluate time-derived state every 60 s so
  a dead agent no longer shows "online" or "running" forever.
- OrderList free-text search broke with a 400 on any comma, parenthesis or
  quote. The PostgREST `or` pattern is now quoted (verified against the live
  API). Tests added.
- Signing out did not clear the TanStack Query cache; the next user on the
  same tab could see the previous user's cached data. `signOut` now clears it.
- "Check Out & Open" in the All-files grid always failed: the request omitted
  `action` and rebuilt the helper URL without `assetId`. It now matches the
  helper-api contract and uses the server-built URL.
- File Hygiene and TIFF Hygiene tabs could never leave "Scanning…" once a scan
  finished (circular pending flag) and polled every 5 s until unmounted.
- The project did not typecheck (23 errors) and CI never ran `tsc`. All errors
  fixed; `npm run typecheck` added and wired into `ci.yml`.

Railway worker (`apps/worker/`)
- Synchronous tagging marked an asset `tagged` before its tags were written;
  a failed tag write left it tagged with zero tags and skipped by every later
  run. The sync path now uses the shared `applyBatchTagResult` (tags first,
  character ids validated, status last).
- `erp-classify` progress dropped `failed`, so a run with a bad API key
  reported success. Failed counts now accumulate.
- OpenRouter `retry-after` was unbounded and `NaN`-prone; bounded to 5–60 s.
  5xx retries now drain the response body so the socket is released.
- The admin-api call in `metadata-reprocess` had no timeout; one hung
  invocation could block the single worker loop. 120 s timeout added.
- A transient config read error switched tagging/classification to the
  hard-coded default model; caches now keep the last known model.

Edge functions (`supabase/functions/`)
- `report-hygiene-findings` upserted against a *partial* unique index, which
  PostgREST cannot target, so every upsert failed and the error was swallowed
  (`hygiene_findings` has 0 rows in production). Now matches open rows,
  updates or inserts, and returns an error instead of a fake success.
- `rebuild-character-stats` read only the first 1000 of ~178k
  `asset_characters` rows and then zeroed every character. Now pages to
  exhaustion and surfaces write errors.
- Agent `get-config` with no `keys` returned the whole `admin_config` table
  (provider secrets included) to any paired agent. Keys are now required and
  intersected with the agent type's allow-list.
- `complete-render` could overwrite a requeued or finished job with a late
  result; it now only completes in-flight jobs.
- A late helper heartbeat could flip a completed/discarded checkout back to
  `uploading`/`verifying`, re-locking the asset. Heartbeats now only touch
  in-progress rows; several checkout writes now check their errors;
  `force-discard` returns 404 for unknown ids.
- `ingest-sibling-images` and `list-sibling-images` accepted `..` path
  segments and arbitrary `thumbnail_url` hosts from any signed-in user. Both
  are now validated with the shared thumbnail-host allow-list.
- `openRouterPublicPricingCache` was a `const` that was reassigned; the
  resulting TypeError was swallowed and the 1 MB catalog was re-fetched on
  every call.

Agents and helper (`apps/`)
- Bridge scanner crash-resume compared paths lexically but walked `readdir`
  in filesystem order, silently skipping unvisited directories after a
  mid-scan restart. Entries are now sorted.
- Windows render agent had no timeout around Sharp/Ghostscript; one hung file
  permanently consumed a concurrency slot. Each render job now fails after
  10 minutes.
- Desktop helper set `checkin_queued` before the stability wait, snapshot and
  API call; any failure left the record stuck in "Queuing check-in…". Status
  now rolls back to `active` on failure.

## Backlog (verified, not yet fixed)

Security / authorization — owner: next PopDAM session
- `admin-api` `USER_ACCESSIBLE_ACTIONS` lets any `auth.users` JWT (no app
  access row) relink assets to any style group and queue bridge folder scans.
  Inputs are now validated, but the access policy itself needs a decision:
  gate on `require_dam_access` (consistent with search) once the app-access
  rows are complete for every real user (see memory: many users lack an app
  role).
- `TAXONOMY_SYNC_CONFIG` stores third-party API keys in a JSON value whose key
  name is not redacted by `admin-config-secret.ts`, so they reach the browser
  in plaintext. Store them under `*_API_KEY` names.
- `browse_dir` on both agents lists any absolute path the cloud sends (no
  mount-root containment). Needs a contract check with the setup UI first.
- `claim-render`/`claim-sg-render` take `agent_id` from the body rather than
  the authenticated identity.
- Helper deep links `popdam://checkin` and `popdam://discard` run with no
  confirmation and no token.

Correctness — owner: next PopDAM session
- Worker terminal `failed`/`completed` writes in `operation-loop.ts` are not
  revision-guarded; a user Stop during the last batch can be overwritten and
  the op auto-resumes.
- `rich-pdf` records a failed extraction under the same text hash, so a
  provider outage permanently marks PDFs as done with empty data. Needs
  `get_pdf_rich_extraction_hashes` to expose `parse_error` (shared-db RPC
  change).
- Export functions paginate with `.range()` and no `ORDER BY`, so large
  exports can duplicate and drop rows; `page_size` not a multiple of 1000
  over-fetches.
- `StyleGroupDetailPanel` "Download all" launches one `popdam://` URL per
  asset; browsers honor only the first. Needs a batch token.
- `StylesPage` invalidates the whole infinite query (and again via realtime)
  on every cell edit.
- `PopSGLibraryPage` name search is not debounced and not cancellable.
- `ResourceAndPolling` resets unsaved slider edits whenever any sibling card
  refetches `admin-config`.
- `AgentSetup` test-render poll has no catch and survives unmount.
- `useScanLifecycle` reports `running → idle` as "Scan complete".
- `normalizeRelativePath` rejects any filename containing `..` (e.g.
  `Final..v2.psd`), not just a `..` segment.
- `shouldSkipPath` applies folder prefix rules (`#`, `$`, `@`, `.`) to
  filenames; such files are silently never ingested.
- `ensureRootMarkers` spawns `docker run` every 30 s forever when a root is
  read-only.
- `.ai` sentinel detection reads up to 100 MB per file into memory at
  thumbnail concurrency; cap at ~16 MB.
- Tesseract workers are not terminated in `finally` in three places.
- `set-user-apps` deletes all access rows before inserting; a failed insert
  leaves the user with none.
- `useAgentStatus.parseCounters` omits two counters the UI displays.
- `AiTaggingSection` labels a per-minute rate as `/s`.
- Unbounded `while (true)` loops in `PopSGSettingsPage`,
  `ScanAndOutputSettings` and `ActionsSection` need an iteration cap.

Efficiency — owner: next PopDAM session
- Relevance-sorted asset/style-group search fetches up to 500 full rows per
  page change and slices client-side.
- `useStyleGroupAssetCount` pages through every matching group 1000 at a time
  to sum a column; needs an RPC.
- `get-filter-options` runs one count query per licensor and per property.
- Worker `buildImageTaggingPrompt` runs ~8 queries per asset with no caching
  of the static ones; `enrichProviderInfo` doubles OpenRouter request volume.
- `fetchOrderListStatusCounts` issues four sequential 2 s counts after every
  save.
- `sell-through-export` fetches thumbnails serially and once per row.
- Every agent heartbeat runs a 3-day `render_queue` prune (a table-scanning
  write every 5–30 s per agent).
- Bridge scanner does `lstat` + `stat` per entry; `Dirent.isSymbolicLink()`
  already answers the symlink question.
- Asset/style-group grids render up to 1000 un-memoized cards per page.

Dead code and duplication — owner: any cleanup PR
- Dead files: `src/hooks/use-mobile.tsx`, `src/pages/LandingPage.tsx`,
  `src/components/library/ScanMonitorBanner.tsx`,
  `supabase/functions/_shared/{erp-mapper,mg-codes,types}.ts`,
  `apps/bridge-agent/src/constants.ts`; retired stubs `sync-external`,
  `classify-erp-categories`, `helper-api /logs`.
- Duplicates: `UsersAndInvitations` vs `UsersTab` (290 lines), three
  `["nas-config"]` queries with different shapes, search helpers copied
  between `useAssets` and `useStyleGroups`, retry/transient helpers copied
  into `admin-api/index.ts` from `_shared/admin-utils.ts`, four pairing-code
  generators, and six modules duplicated between the bridge and Windows
  agents that are already drifting (`callAiVision` has a `meta-direct/` route
  on Windows only).
