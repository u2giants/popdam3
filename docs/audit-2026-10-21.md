# Codebase audit — 2026-10-21

Five parallel reviewers read the web app, the Railway worker, the Supabase edge
functions, the agents, the desktop helper and the scripts. Every finding below
was verified by reading the code; the first section landed in the audit PR,
the second section is the backlog, most urgent first, each with a suggested
owner. Nothing here changes the shared database.

## Fixed in the audit PR

Web app (`src/`)
- "View as member" never worked: the role-level `ImpersonationProvider` was
  defined but never mounted, so `useIsAdmin` and the header read a no-op
  default context. Now mounted in `App.tsx`.
- Realtime subscriptions in `useAgentStatus`, `useScanProgress` and
  `useCrawlProgress` shared one channel topic; whichever consumer unmounted
  first tore down the live subscription for the others. Topics are now unique
  per mount, and both status hooks re-evaluate time-derived state every 60 s so
  a dead agent no longer shows "online" or "running" forever.
- OrderList free-text search broke with a 400 on any comma, parenthesis or
  quote. The PostgREST `or` pattern is now quoted (verified against the live
  API). Tests added.
- Signing out did not clear the TanStack Query cache; the next user on the
  same tab could see the previous user's cached data. `signOut` now clears it.
- "Check Out & Open" in the All-files grid always failed: the request omitted
  `action` and rebuilt the helper URL without `assetId`. It now matches the
  helper-api contract and uses the server-built URL.
- File Hygiene and TIFF Hygiene tabs could never leave "Scanning…" once a scan
  finished (circular pending flag) and polled every 5 s until unmounted.
- The project did not typecheck (23 errors) and CI never ran `tsc`. All errors
  fixed; `npm run typecheck` added and wired into `ci.yml`.

Railway worker (`apps/worker/`)
- Synchronous tagging marked an asset `tagged` before its tags were written;
  a failed tag write left it tagged with zero tags and skipped by every later
  run. The sync path now uses the shared `applyBatchTagResult` (tags first,
  character ids validated, status last).
- `erp-classify` progress dropped `failed`, so a run with a bad API key
  reported success. Failed counts now accumulate.
- OpenRouter `retry-after` was unbounded and `NaN`-prone; bounded to 5–60 s.
  5xx retries now drain the response body so the socket is released.
- The admin-api call in `metadata-reprocess` had no timeout; one hung
  invocation could block the single worker loop. 120 s timeout added.
- A transient config read error switched tagging/classification to the
  hard-coded default model; caches now keep the last known model.

Edge functions (`supabase/functions/`)
- `report-hygiene-findings` upserted against a *partial* unique index, which
  PostgREST cannot target, so every upsert failed and the error was swallowed
  (`hygiene_findings` has 0 rows in production). Now matches open rows,
  updates or inserts, and returns an error instead of a fake success.
- `rebuild-character-stats` read only the first 1000 of ~178k
  `asset_characters` rows and then zeroed every character. Now pages to
  exhaustion and surfaces write errors.
- Agent `get-config` with no `keys` returned the whole `admin_config` table
  (provider secrets included) to any paired agent. Keys are now required and
  intersected with the agent type's allow-list.
- `complete-render` could overwrite a requeued or finished job with a late
  result; it now only completes in-flight jobs.
- A late helper heartbeat could flip a completed/discarded checkout back to
  `uploading`/`verifying`, re-locking the asset. Heartbeats now only touch
  in-progress rows; several checkout writes now check their errors;
  `force-discard` returns 404 for unknown ids.
- `ingest-sibling-images` and `list-sibling-images` accepted `..` path
  segments and arbitrary `thumbnail_url` hosts from any signed-in user. Both
  are now validated with the shared thumbnail-host allow-list.
- `openRouterPublicPricingCache` was a `const` that was reassigned; the
  resulting TypeError was swallowed and the 1 MB catalog was re-fetched on
  every call.

Agents and helper (`apps/`)
- Bridge scanner crash-resume compared paths lexically but walked `readdir`
  in filesystem order, silently skipping unvisited directories after a
  mid-scan restart. Entries are now sorted.
- Windows render agent had no timeout around Sharp/Ghostscript; one hung file
  permanently consumed a concurrency slot. Each render job now fails after
  10 minutes.
- Desktop helper set `checkin_queued` before the stability wait, snapshot and
  API call; any failure left the record stuck in "Queuing check-in…". Status
  now rolls back to `active` on failure.

## Re-verification 2026-11-04

replaces the old backlog list; open work lives only on the issues named here.
