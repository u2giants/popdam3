# PopDAM and PopSG code audit

The largest risks are to original artwork, style-group membership, and confidence that a designer’s check-in actually completed. The evidence below identifies conditions under which the code can fail. It does not establish that customer files have already been lost.

Track the 24 findings and six child issues in the [November 18 audit backlog](https://github.com/u2giants/popdam3/labels/audit-2026-11-18).

## Scope and evidence

The supplied workspace contains one project repository, u2giants/popdam3. Its other Git checkouts are working copies. PopSG shares its code. This report covers the main branch at 98ed424bc0e5, verified against the remote on November 18, 2026. Source references are repository-relative at that revision.

The review inventoried the frontend, backend, all seven application packages, shared libraries, scripts, migration utilities, deployment files and workflows. Reviewers searched across components and traced selected operations through callers, error handling and storage. This was a repository-wide, risk-based inspection, not a line-by-line certification. External services, the independently owned shared-database repository, generated copies, dependencies, private artifacts and other sessions’ edits were outside scope. The frontend type check passed. No live operations, attack testing, repairs or deployments were performed. All 39 selected offline checks for folder planning, search scoring and write measurement passed. Those checks do not exercise the failure scenarios below.

**Confidence is high for the cited code behavior throughout.** Severity reflects the consequence if the stated condition occurs. Frequency and historical impact were not measured.

## High severity

1. **TIFF optimization can discard pages of original artwork.** The Windows fallback explicitly selects the first page. The replacement check compares byte size and timestamps without validating page count. In replacement mode a smaller, single-page result can take the original’s place and the backup is then deleted. An offline two-page test TIFF shrank from 1,824 bytes to 262 bytes and retained only one page with the normal compression library. Evidence — apps/windows-agent/src/tiff-optimizer.ts:350,372,495,533,570.
2. **Artwork cleanup can delete a style group that still contains active artwork.** Both cleanup actions use one unpaginated list of remaining asset rows to decide which groups are empty. A failed lookup becomes an empty list. A capped result can also omit a group. Both paths then request permanent deletion of the groups they missed. Evidence — supabase/functions/_shared/admin-handlers/purge-handlers.ts:54–73,161–173.
3. **Check-in can report success and discard the retry even after a failed save.** Direct check-in ignores the results of separate checkout and asset updates. The verification route also acknowledges an unchecked save. The desktop Helper removes the job when either success response arrives. The designer can see completion while the record stays locked or references the previous file details. Evidence — supabase/functions/helper-api/index.ts:453–500 and apps/popdam-helper/src/main/uploadQueue.ts:198.
4. **A failed count silently removes an entire table from a migration export.** The manifest discards the database error and records zero rows. The downloader then skips that table. A complete-looking export can therefore omit records that existed. Evidence — supabase/functions/export-sql-dump/index.ts:109–118 and migration/download-sql-dump.ps1:69–75.
5. **A failed download can feed an incomplete or mixed SQL restore.** The downloader continues after a missing chunk, reuses an existing directory and directs the operator to import every SQL file there, including leftovers. Its default first chunk clears the destination table; a later missing chunk leaves it only partly restored if the instructions are followed. Evidence — migration/download-sql-dump.ps1:20–34,85–108 and supabase/functions/export-sql-dump/index.ts:172–174.

## Medium severity

6. **A failed file swap can leave artwork missing at its normal location.** The Windows agent moves the original to a backup name before installing the compressed file. If the second rename fails, the exception path cleans the temporary file without moving the original back. Recovery is possible from the backup. Evidence — apps/windows-agent/src/tiff-optimizer.ts:400–428,515–546.
7. **A desktop interruption can erase pending check-ins from the retry list.** The Helper rewrites the queue directly. A partially written queue reads as empty and the next enqueue replaces it. The artwork snapshot may still exist, but the Helper loses its pending work. Evidence — apps/popdam-helper/src/main/uploadQueue.ts:86–110.
8. **A failed sign-out can leave a shared workstation signed in without warning.** The header calls a sign-out wrapper that ignores the returned error. A service failure can leave the locally persisted session active. Evidence — src/hooks/useAuth.tsx:47, src/components/AppHeader.tsx:667 and src/lib/external-supabase.ts:17–19.
9. **Checkout status can mislead a designer in two ways.** A failed lock lookup offers Check Out on an already locked asset. When the lock is found but its owner profile cannot be loaded, the interface compares profile email instead of the known owner ID and can hide Check In from the actual owner. Evidence — src/hooks/useAssetCheckout.ts:16–33 and src/components/library/CheckoutBar.tsx:17–25,66–76.
10. **The update screen can confirm installation before the agent has updated.** It accepts an online status five seconds after requesting installation, while a heartbeat from before the request still counts as online. A separate update check accepts an earlier result without matching the request. Evidence — src/pages/settings/AgentStatusSection.tsx:45–59,73–86 and supabase/functions/_shared/admin-handlers/agent-handlers.ts:100.
11. **Checking for an update on the bridge also triggers Windows renderers.** The bridge card issues a check; the backend sets the immediate-update flag on every Windows renderer even for that check. The renderer acts on that flag. Evidence — src/pages/settings/AgentStatusSection.tsx:58,406 and supabase/functions/_shared/admin-handlers/agent-handlers.ts:729–747 and apps/windows-agent/src/commands/heartbeat-commands.ts:121–125.
12. **A scan can acknowledge missing previews without scheduling them.** Lookup and insertion failures are discarded before returning success. Files needing this alternate rendering path can stay without previews. Evidence — supabase/functions/agent-api/index.ts:2306–2334.
13. **Character usage recalculation can leave valid counts and priority flags cleared.** It resets the catalog first, then saves each character in a separate request. A failure midway leaves later characters at zero until a successful rerun. Evidence — supabase/functions/admin-api/index.ts:673–688.
14. **Large SQL export requests can skip consecutive blocks of records.** The manifest and downloader use the requested chunk size, while the exporter returns at most 10,000 rows. For a 20,000-row request, the next offset advances by 20,000 after at most 10,000 returned. The shipped 5,000-row default avoids this condition. Evidence — supabase/functions/export-sql-dump/index.ts:109–115,132–145 and migration/download-sql-dump.ps1:21,74.
15. **The CSV exporter reports completion after errors and can overwrite a good export with a partial one.** After a later page fails, it writes the earlier pages to the normal filename. A first-page failure is labeled an empty table. Its own default table list includes an administrator-settings table the server expressly excludes. Evidence — migration/export-all-tables.ps1:25,118–134 and supabase/functions/export-table/index.ts:13–36,61–65.
16. **A bounded image-indexing run can exceed its work limit and finish as a failure.** It claims a full batch, processes it, then raises an exception when the limit is reached. In drain mode that exception exits before the intended normal completion branch. An offline queue test processed three jobs with a limit of one and raised the exception. Evidence — apps/image-embed-worker/image_embed_poller.py:481,555,951–965,1029.
17. **The thumbnail export can exhaust memory as the catalog grows.** It fetches pages but retains every output row, then joins the complete export before sending the first byte. Peak memory grows with the entire catalog. Evidence — supabase/functions/export-thumbnail-manifest/index.ts:44–60,75–78.
18. **The worker can say it recorded a new SeaDrive installer while the old entry remains.** The database can return a write error without throwing. The worker ignores that result and records success in its log. Evidence — apps/worker/src/handlers/seadrive-mirror.ts:229–235.

19. **Master Data can show an empty review queue when loading fails.** The screen displays an error alongside zero awaiting review and “Nothing is waiting for a decision.” The empty message also appears when a filter hides outstanding reviews. Evidence — apps/db-data-admin/src/PropertyMatchReview.tsx:58–65,154,232–234.
20. **Two quick folder selections can open the wrong folder.** Earlier and later requests share one polling handle. A delayed result for the first selection can cancel polling for the second and replace its listing. Polling can also issue overlapping requests every half-second. Evidence — src/components/settings/DirectoryBrowserTab.tsx:77–123,208,249.

## Low severity

21. **Style-guide filters can omit licensors or properties.** Filter choices come from one ordered query capped at 5,000 folder rows; duplicate folder entries consume that allowance before deduplication. Later names can disappear without an overflow notice. Evidence — src/pages/popsg/PopSGLibraryPage.tsx:778–794.
22. **Preview audits resend earlier results after every batch.** Both scanning agents send the full accumulated list each time and suppress progress-update errors. With a steady rate of flagged images, doubling the batch count roughly quadruples total result traffic. Evidence — apps/bridge-agent/src/handlers/compat-audit.ts:84–90 and apps/windows-agent/src/compat-audit.ts:248.
23. **Batch text search accepts much larger inputs than individual search.** Individual requests limit text to 8,000 characters. The batch route limits the number of strings only, so it can accept and process large strings before truncating model input. Evidence — apps/text-embed/main.py:69–76,88–93,207–213.
24. **Operational logs retain email addresses and full subject lines.** Every outbound email sends those fields to logs accessible to operational readers, and provider responses are logged in full. The finding concerns unnecessary exposure within logs. Evidence — supabase/functions/_shared/brevo.ts:49,68–72.
